# Target-row binding rival: development result

The target-binding intervention tests a fault at a different locus from score-column mapping. Mapping changes how the positive-class score column is read. Target binding leaves the model, calibration, both score columns, row IDs and scorer unchanged, but feeds each selected evaluation row the target of a donor row. Two development constructions exercise this locus: an untuned cyclic permutation and an adversarial paired donor ledger. Correction restores the original target-row binding.

The cyclic selector depends only on source/dataset and row IDs. It does not consult scores, targets, model outputs or observed loss. A cyclic donor mapping preserves target class counts; same-label donors are retained as structural negative controls. Dose 0 is a sham. The paired construction consumes disjoint opposite-label row pairs selected by the existing development symptom matcher. That search deliberately uses development targets, scores and the mapping metric. The target injector itself only applies the donor join and never calls the score-column mutation. Both constructions preserve the class counts.

The independent verifier reconstructs the donor mapping and score-source witness without invoking the injector or correction helper. It checks source target/score hashes, donor lineage, class counts, runtime-scored log-loss, and exact corrected restoration. A hash establishes the identity of captured bytes, **not** that original target labels are semantically true.

An offline development run on the two pinned P2 sources × two estimators × doses 0, 1, 2 and 4 gave four zero-dose flat cells and 12/12 nonzero-dose loss increases. Every cell preserved class counts and restored the exact healthy loss after correction (16/16). No provider call or sealed/final holdout was used. These 16 measurements share rows, sources and nested doses; they are not independent replicates or a population effect estimate. The item-level rows and fitted objects remain private.

The untuned cyclic comparison has **0/12** byte-equal nonzero-dose `missing_key` payloads at both six and twelve decimals; `full` also differs in 12/12. Its visible shortcut is the observed log-loss and loss change (for example, +0.013636 versus +0.020488 in one cell). This negative control is retained.

The paired replay loads the exact previously selected pair ledger from a hash-confirmed predecessor. It reapplies each donor join through the typed target injector and independently verifies the upstream witness, targets, donor mapping, footprint and correction. All 12 pairs replay the prior target-vector hash and runtime loss. All 12 preserve class counts and restore the healthy loss. The serialized `missing_key` views are byte-identical to their mapping counterparts at six decimals in **12/12** pairs; all 12 `full` views retain a distinguishing witness. At twelve decimals, **0/12** `missing_key` views match. Raw loss gaps range from approximately 4.30e-11 to 3.60e-8. The six-decimal precision was inherited from the predecessor and was not adjusted during donor replay.

| Construction | Six-decimal `missing_key` equal | Twelve-decimal `missing_key` equal | `full` distinguishes | Correction exact |
| --- | ---: | ---: | ---: | ---: |
| Untuned cyclic donor | 0/12 | 0/12 | 12/12 | 12/12 |
| Development-selected paired donor | 12/12 | 0/12 | 12/12 | 12/12 |

This completes the development implementation and observation check. The paired replay strengthens provenance for the **same existing development pairs**; it adds neither fresh independent observations nor a generalization test. Within each equally weighted pair, a classifier seeing only the identical six-decimal payload cannot exceed 50% expected pairwise accuracy without additional information. This statement does not apply to unequal cause priors, twelve-decimal inputs, accessible donor metadata, or new families. Byte equality supplies that restricted result directly; no LLM run is required to establish it.

Prospective testing must fix the observation precision, matching algorithm, footprint bound, failure handling and new sources before outcome access. It should retain unmatched cases and test that the actual diagnosis payload exposes neither higher-precision metrics nor mechanism metadata. Independent mechanism admission remains a later decision. The donor replay alone does not authorize a holdout or a registered experiment.

The offline CLI accepts `--root`, `--prior` and `--output`. To replay adversarial pairs as well, add `--matched-prior` and its exact `--matched-prior-sha256`. Inputs and outputs must be private sibling directories; an existing output is never overwritten. The resulting summary contains both constructions and their precision checks, with the predecessor byte hash.

The methodological motivation is standard model-based fault diagnosis: a cause is not identified merely because an injected fault changes an outcome; competing hypotheses must be distinguished by an observable witness. Aletheia's contribution would be the operational measurement of that condition on ML-pipeline artifacts, not a claim to have invented diagnosability. See [Reiter's model-based diagnosis](https://doi.org/10.1016/0004-3702(87)90062-2), [de Kleer and Williams' multiple-fault diagnosis](https://doi.org/10.1016/0004-3702(87)90063-4), and the [scikit-learn positive-class confusion discussion](https://github.com/scikit-learn/scikit-learn/issues/17572) for the distinct score-mapping failure family.
