# Prospective serving contract-boundary checks

This local tool checks a **design declaration**, not a serving execution or a
scientific result. A structurally valid proposal never authorizes an experiment.
It is separate from the historical model-load and request-model studies.

## Query-relative model

An audit question depends on its contract, changed components, actual refresh
action, bindings retained at use, request/activation association, and declared
immutability/capture assumptions. “Reload”, a matching output, a module ID or a
signed current file is not a complete state reference.

Keep five questions distinct: actual used state, authorization for the request,
numerical correctness against a separately specified target, persistence within
a named recovery tier, and correct scoped delivery within the accepted deadline.

Mixed versions may be authorized. Signing new files without activation may leave
the previous epoch authorized while failing to attain an upgrade target. Failed
upgrade, contract violation and failed audit service are different outcomes.

## Fair comparison and reference

Declare full-closure official signing, complete actual native/history, and strong
integrated ordinary evidence separately. The ordinary view may use legitimate
per-request state instrumentation; do not weaken it to create candidate advantage.
Candidate and ordinary join use identical records. Reference serialization is
separate, but facts accessible to legitimate operator instrumentation are not
forbidden merely because they concern state.

Consider a richer witness only after a demonstrated development gap and give it
to both checkers. Unknown does not establish universal native insufficiency; an
equal-observation counterexample applies only to the exact projection held equal.

## Read-only proposal inspection

```sh
PYTHONPATH=src python scripts/serving_contract_design.py --design /path/to/design.json
```

The schema declares bounded development/validation paths with exact source byte
pins; explicit source/framework/mechanism/outcome exposure; separate control and
reference qualification; no main update/fault calls; baseline evidence rights;
query-relative assumptions, missing witnesses, repairs and falsifiers; and a
complete failure/unknown/refusal/unattempted census without outcome retries.

The inspector rejects source-blind claims after source reading, corpus labels as
runtime-model inputs, leaked reference fields, overlapping development/validation
source groups, duplicate IDs, missing requirements declared sufficient, and
nonconclusive expected answers labelled sufficient. The CLI rejects symlinks,
nonregular files and oversized inputs; it writes nothing and prints no private
path or design payload.

Successful inspection returns scientific verification, execution readiness and
authorization as **false**, even when controls are self-declared qualified. It
checks declarations only: no authentication, execution enumeration, completeness
proof or framework run. Execution requires a reviewed design, qualified actual
references, and a separately sealed adapter/analysis before outcomes.

## Transfer and human coding

New-operation outcomes after source exposure are not source-blind discovery, an
unseen framework or a natural deployment. Health does not qualify a watcher or
actual-use reference. Untriggered treatment remains in the census, not a success.

Corpus coverage cannot revise a frozen model and retain the exposed runtime frame
as validation. Calibration, main coding and pre-adjudication reliability remain
separate; adjudication does not increase the original agreement statistic.

This proposal checker establishes no hostile-host completeness, arbitrary
dependency discovery, power-loss guarantee, global cost optimum, new retention
algorithm or publication outcome.

## Scoped query consumer

`serving_contract_evidence.resolve_queries` is an ordinary join, not a learned
checker or new tracing algorithm. It receives lawful observations and public
policy; evaluator reference fields are rejected. Positive graph identity requires
a separately verified finite source/operand/actual-use/read-only/dependency-scope
qualification receipt, not a matching digest or `projection_complete` alone.

Authorization uses public enrollment, numerical correctness uses declared input
and specification, and persistence compares the actual recovered event, commit-ACK
and retrieval digests. Accepted service additionally checks scoped delivered
answers and same-clock offer/admission/delivery/deadline order. Missing evidence
remains unknown; association conflict, refusal and lateness remain distinct.
An accepted unknown/late answer stays accepted-but-unserved. A prediction response
is not a collector ACK or audit admission.

The consumer cannot authenticate trusted host observations, discover every native
dependency or turn synthetic tests into transfer evidence. Identical lawful records
may produce an ordinary/candidate tie; this is not candidate superiority. Strong
load-bound immutable evidence must be credited via its own qualified proof chain,
not fabricated as a request capture or discarded to create a gap. Native initial
control, approval, execution seal, development and reserved validation are distinct.

## Prospective breadth and resident instrumentation amendment

The amendment schema retains the predecessor proposal and journal identities.
It requires four framework domains and five distinct operations: inline object
construction, replica reconfiguration, replica replacement, an official watcher
with outside-root acquisition contrasts, and explicit/default version routing.
Routing is not mislabeled as recursive refresh. Required paths cannot be silently
downgraded to optional after qualification failure.

Four ordinary evidence projections are distinct:

- V0: full declared signing closure.
- V1: complete actually available native/history evidence, not deliberately
  restricted logs. Richer native records must receive credit.
- V2a: strong lifecycle/enrollment/request association with declared immutability.
- V2b: V2a plus lawful, uniform, query-specific acquired resident measurements.

V2a can already suffice for a properly bound immutable session. V2b is not a
guaranteed improvement and is not allowed privileged evaluator serialization.
The same measurements go to both ordinary join and candidate. Eight prospective
risk groups must link registered conditions and concrete same-path predictions;
listing mechanism names alone is not coverage.

`resident_state_capture` fingerprints explicitly acquired finite values. It
preserves types, array dtype/shape/content, and selected Python callable code,
defaults, closure and declared globals. It does not discover dependencies or
automatically prove which values execution used. The adapter must acquire a
use-local immutable snapshot or hold synchronization across measurement and use.
Equal generation tokens alone do not prove that discipline.

Opaque native objects, dynamic/transitive unregistered state, unsupported values,
cycles and budget excess remain unknown for queries requiring them. No disk,
output, object ID or `repr` fallback replaces resident state. Cardinality and
string limits are checked before large sorting/encoding allocation. These tests
are instrumentation contracts, not native transfer or completeness experiments.

For ONNX Runtime, a Python session object ID is not a permanent native session
generation: provider reset/fallback may rebuild it. Immutable enrollment claims
therefore require an explicitly bounded provider/reset policy and closure scope;
native weights are not claimed as readable through generic Python fingerprinting.

Only incremental V2b instrumentation versus V2a may justify a new matched-service
cost measurement. Previously measured layout outcomes remain unchanged. Native
qualification, reference qualification, human checkpoint approval and execution
sealing are separate from this declaration checker.

## Fault-independent acquired graph

`resident_footprint.capture_entry` starts from the actual selected Python entry,
its bound receiver, a declared package boundary and fixed budgets. There is no
argument for a fault, expected state or list of changed component names. Decoded
`LOAD_GLOBAL` bindings are distinct from attribute names. Live helpers, defaults,
closures, nested code and supported static receiver attributes are traversed
passively. Properties/custom lookup are never executed. Discovery charges both
edges and decoded instructions before the final encoder, not only graph objects.

This record is a bounded **potential acquired graph**, not an executed call slice.
An unsupported edge sets a partial status even if a useful partial hash exists.
Mutation/import/unsupported namespace edges prevent a complete projection claim.
Dynamic dispatch can remain outside the rule. A negative control must distinguish
honest unknown from a wrong conclusive answer; failure to detect while declaring
compliance is not a successful negative control.

Even `projection_complete=true` is not a state-sufficiency verdict. These fields
remain explicitly false: actual dependency use, verified package ownership,
acquired input operands, implicit-dispatch coverage and established sufficiency.
Package names are declared scope labels, not origin attestation; fixed builtin
identities do not establish purity on arbitrary arguments. Native adapters must
separately qualify owned source, operand types, capture-through-use discipline,
readonly/actually consumed snapshot and the dependencies required by the query.
An equal generation token or a common lock alone cannot cover mutation performed
inside the callable. Unqualified queries remain unknown, while independent
numerical, persistence or delivery evidence can still answer their own questions.

The optional capture amendment checks atomic forecast provenance separately as
`doc-stated`, `pinned-source-derived` and `model-composed`. Explicitly assigned
state, initial sanity checks, equal-output controls and authored deadline controls
must not inflate the primary forecast denominator. Source-informed native
validation is not blind discovery. The checker still grants no execution authority.

## Subsequent concurrent-selection and cache extension

A separately approved, source-informed extension retained 116 non-cost request
opportunities and 640 ResNet serving calls. These are controlled authored loads
and schedules, not independent natural incidents or source-blind predictions.

Of the non-cost requests, 105 completed natively and 92 had qualified raw
references. Only 80 reached the intended mechanism, including coverage and
controls. Host strong views answered 30 of 36 scoped audits correctly/on time;
isolated Linux Ray answered 62 of 80. Twelve further Ray persistence ACKs belong
to unqualified contexts and cannot be counted as verified served audits. All
failed and unreached requests remain in the denominator. Ordinary enriched
history/use records and resident probing tie; unaugmented native logs are not
the baseline represented by these results.

Native Ray multiplexing retained a cached edition after publication under the
same model key. Eviction followed by reacquisition or immutable versioned keys
acquired the appropriate published edition. Actual cache eviction did not
invalidate a fitted object still held by an entered request; the finite tested
object has no destructive cleanup, so arbitrary native/GPU lifetimes are outside
scope. Under a separately declared newer-edition target, a stale selected state
can violate identity even when an equal-input/output control remains numerically
equal. This is not a violation of the documented cache contract.

TorchServe registration alone retained the old default. A successful default
switch left an already-entered old handler unchanged while the post-switch
request selected the new version. Held/post request execution intervals actually
intersected in the default-switch contexts; register-only had management-update
overlap but not two intersecting request intervals. Both entry-cutover and
post-ACK-entry contracts allow an old immutable request selected before ACK to
finish afterward. Completion time is not a replacement selection boundary.

The included-root Bento worker cutover did not qualify under load. The extension
Ray adapter reconstructed an imperative deployment graph and replaced actors,
so it did not establish the specified same-actor reconfigure/in-place mechanism.
The resulting held-request failures are adapter-fidelity gaps, not SDK bugs,
verified mutation results or successful forecasts. Source exposure, these gaps
and the original failures are retained. Endpoint-only ABA remains a theoretical
equal-observation limit, not a new native experiment.

Fourteen prospective declarations are reported by origin: doc-stated two
supported/one unidentified, pinned-source-derived five supported, and
model-composed two supported/four unidentified. Documentation and cache/LRU
controls are not new inferred discoveries. Zero conclusive mismatches on the
qualified references does not prove safety in the unqualified mutable/in-flight
mechanism. The strong writable-array load proof abstains; a richer lawful
actual-use snapshot is separately credited to both consumers.

### Incremental probing cost on the existing large ONNX artifact

Twenty fresh MLServer/ORT workers served 640 calls through the native registry
and data-plane path, with 90 serving loads on the 169.799 MiB ONNX closure.
The same static amortized generation store, WAL/FULL/batch-eight persistence,
full-closure verification, input/output hashing and delayed query/reopen service
were used by both physical arms. Common recovery added 20 loads and 60 replay
calls, charged equally and excluded from the serving-opportunity denominator.
Historical storage-layout and native-floor studies were not rerun.

All 640 retained vectors match the independent existing numerical reference.
One worker's process monitor reported an inspection `AccessDenied`; its 32 ACKs
remain unverified/unserved despite terminal native completion. Thus 608 requests
have guard-qualified fulfilled service. At equal verified scoped service, added
resident probing increased median workload-through-final-ACK time by 4.636%
for reuse (five pairs; range 4.414–6.591%) and 3.544% for reload (four qualified
pairs of five planned; range 2.590–4.436%). The unqualified reload pair's raw
negative delta is retained, not counted as a qualified timing contrast.

Both arms answer the same narrower artifact-generation query under trusted
verified-constructor/use/no-reset assumptions and full-vector numerical query.
Opaque native resident weights remain unknown in both; probing adds no coverage
for this scoped service. These are descriptive paired measurements, not a global
minimum, production throughput, cold-cache, crypto-only or universal advantage
claim. Explicit hashes nested in signature verification, defensive hashes within
write, retrieval integrity checks and audit rehashes are not summed as disjoint
latency. The extension supports keeping the ordinary baseline where its evidence
and service assumptions hold, not claiming a new optimizer or checker win.

## Final configuration-path correction and bounded scope

A prospectively approved, separately identified technical follow-up used Ray's
official configuration deployment path with unchanged import path/builder args
and only `user_config` changes. A distinct benign label fixture verified the same
actor/PID and reachability of an entered request's old barrier after update.
Exact source seals then preceded 30 new requests in ten fresh isolated Linux
contexts. All requests completed with qualified raw snapshot/source/arithmetic
references, preserving the actor across each update. Six contexts contained real
overlapping request intervals; sequential context processes are not throughput.

Immutable replacement retained the held old bundle while post-update selection
used the new one. In-place updates preserved object and array identity but changed
consumed state, invalidating the own immutable-load proof. Complete lawful
actual-use history still identified all 30 consumed states. The enriched ordinary
views and resident-probing view each served 28 full audits correctly on time;
two mutable held requests retained unknown authorization/numerical-under-target
because the unchanged immutable-bundle contracts do not define a coherent mutable
target. All 30 persisted ACKs remain accepted, including the two unserved audits.
Both entry policies permit an old immutable selection made before ACK to complete
afterwards. No qualified per-query false confidence was observed.

The declared inadequacy falsifier was triggered: missing load immutability did
not defeat complete ordinary actual-use evidence. The mutation premise remains
supported; it is not evidence for a new checker advantage. Six offline mismatches
from blindly using stale load weights are misuse diagnostics, not errors by the
implemented strong baseline. The proposed different-held-contract-score clause
is unsupported, even though the retained old/new mechanism was observed.

Bento's separate benign included-marker qualification reached a new worker, but
the held request timed out at its predeclared 55-second ceiling before readiness;
the post-ready request completed without successful held/post overlap. Six new
main allocations were therefore refused at qualification, not executed or counted
as transfer successes. The increased observation budgets, original failures and
failed qualification are retained. No further amendment was opened.

The held-request interruption is a bounded availability observation of the benign
watcher setup, not evidence of successful model repair or a general framework bug.

Read-only checks covered 44 stores, 171 events, 120 request/ACK joins and 240
policy/recovery joins; no privileged reference was persisted in lawful evidence.
No cost study was rerun. These results support a bounded trusted-source lifecycle
account of evidence premises and ordinary sufficiency. Successful Bento included
overlap repair, general mutable authorization/atomicity, hostile-host completeness,
natural deployment and global optimality remain outside the supported claims.

The accepted scientific scope is frozen at these qualified results. Retention
and ACK non-fulfilment remain negative findings in the lifecycle account; they
do not establish a separate admission/retention algorithm contribution.
