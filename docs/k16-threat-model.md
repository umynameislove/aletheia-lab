# Hosted threat boundaries and local evidence (K16)

The attacker controls HTTP input, imported project bytes and application text. The API must derive identity from a live server session, authorize every workspace/object operation, validate a current mutation proof, and prevent source text from gaining network/process authority. The database, process configuration, host filesystem and authorized deployment operator are trusted components with separate operating controls. Provider results and restored files still require validation.

| Boundary / threat | Existing control and regression evidence |
|---|---|
| Host/proxy confusion | Exact configured HTTPS authority; client forwarding headers cannot change effective scheme/client. `test_k02_edge.py` covers wrong/ambiguous hosts, spoofed forwarding and the process adapter. TLS termination/certificate validity must also be checked at the deployed edge. |
| Login/open redirect/cookie injection | Exact return-path policy, issuer/callback shape, opaque host-only Secure/HttpOnly/SameSite=Lax cookies; ambiguous cookies denied. `test_k03_auth_boundary.py` exercises redirect and cookie/header-injection negatives. Parsing a callback code is not proof of verified identity; actual IdP acceptance remains separate. |
| CSRF/session confusion | Current server binding, signed context-bound proof, exact origin, fetch metadata, bounded headers/body and no bearer/method-override bypass. `test_k03_csrf_boundary.py` covers duplicate headers, wrong context/signature, expired binding, lookup cancellation and cross-site requests before effects. |
| Tenant/role/object access | Every repository/HTTP operation resolves the session and checks current membership/version; opaque IDs are not authorization. K06/K09/K10/K11 scoped integration suites exercise denied foreign objects, stale roles and committed effects. Run those with the release's DB receipt; this document does not turn an unrun case into a pass. |
| Path traversal/symlinks/code execution in import | Ingestion treats notebooks/text as data, rejects symlink chains/loops, aborts malformed mixed projects and reconciles executable files without admission. `test_project_ingestion_security_regressions.py` exercises these actual local parsers with malicious instructions. Uploaded archives additionally retain existing entry/depth/expanded-byte limits. |
| SSRF/program launch in PDF rendering | URLs/images/project text remain inert text; isolated renderer denies network and program launch. `test_k12_pdf.py` runs real child policy refusal and Unicode/precision parity. Remote links are not fetched on the server. |
| Secret disclosure/log injection | Safe response problem codes and request IDs; formatter never interpolates arguments/exceptions/untrusted extras. `test_k16_observability.py` injects raw secrets/newlines through actual adapter errors and third-party diagnostics, bounds a blocked collector, and verifies fixed metric cardinality across 250 private object paths. |
| Resource exhaustion/noisy tenant | Existing upload/quota/lease controls plus K14 shared blocking admission, HTTP reserve and polling bounds. Runtime snapshots expose fixed active/waiting/rejected counters. Load/fairness evidence belongs to K17; source limits and unit tests alone do not establish capacity. |
| Supply-chain drift | Production closure/constraint check, path-free SPDX SBOM, installed metadata/license hashes, time-bound vulnerability audit. Artifact-hash locks and built-image qualification remain K18/operator work. Four unresolved license declarations remain explicit review items. |

Residual deployment checks include real IdP behavior, external secret/collector permissions, proxy/TLS and security-header observation, built image/non-root execution, deployed paging delivery, tenant fairness under the declared workload, and source/object/backup lifecycle controls. These are explicit boundaries of the local receipts, not inferred passes. No current vulnerability finding is a substitute for authorization, correctness or restoration checks.
