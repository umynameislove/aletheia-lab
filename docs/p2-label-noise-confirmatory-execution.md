# Registered label-noise confirmatory execution

> Status: execution implementation validated against synthetic fixtures; no
> registered outcome has been generated by this change.

This document defines the operational boundary between the frozen protocol and
the single registered outcome batch. The scientific design remains exclusively
defined by
`configs/benchmark/p2_label_noise_confirmatory_protocol.json`, SHA-256
`1a7340d0897fcbbde02bb0a3ffe0a50cccd1cebd695ebf2c293c6c260bb02d4e`.

## Preconditions

Registered execution is permitted only when all of the following are true:

1. the execution implementation has been merged to `main` and CI passes on
   Python 3.11 and 3.12;
2. the worktree is clean and local `main` equals `origin/main`;
3. annotated tag `p2-label-noise-confirmatory-v2` resolves to the protocol
   commit and is an ancestor of the execution commit;
4. GitHub exposes a non-draft, non-prerelease, immutable release for that tag;
5. the primary snapshot, external archive and external CSV match their frozen
   SHA-256 digests;
6. the operator explicitly confirms both the protocol and registration hashes;
7. the output store does not already exist.

Failure of any precondition is a governance failure and must occur before a
sealed outcome is opened.

## Outcome-blind preflight

After the implementation is merged, run:

```bash
python scripts/p2_confirmatory_closeout.py preflight
```

Preflight verifies predecessor receipts, Git state, the tagged protocol,
immutable GitHub release and all source bytes. It downloads and extracts the
official nested UCI archive without parsing labels or constructing a test
partition. Its report must state:

```text
sealed_test_opened: false
outcomes_generated: false
```

The generated registration receipt is content-addressed. Re-running preflight
may reuse an identical receipt but cannot overwrite different evidence.

## Single registered batch

Use the exact hashes printed by preflight:

```bash
python scripts/p2_confirmatory_closeout.py execute \
  --confirm-protocol-sha256 <protocol-sha256> \
  --confirm-registration-sha256 <registration-sha256>
```

This one command performs the complete locked sequence:

1. re-verifies clean synchronized Git state, predecessor receipts, tag and
   registration receipt;
2. loads both byte-pinned datasets and excludes Bank `duration`;
3. creates the frozen Telco stratified and Bank temporal split manifests;
4. fits preprocessing only on each training partition;
5. executes all six direction-by-dose cells and all 30 seeds per cell for both
   datasets;
6. executes the clean, serialization, matched symmetric and repair controls;
7. reconciles exactly 180 replicates per dataset with no missing, additional,
   duplicate or replayed cell-seed pair;
8. applies the registered 10,000-sample crossed bootstrap, 100,000-sample paired
   sign-flip tests and Holm correction;
9. derives the primary-precedence decision only after both datasets complete;
10. atomically publishes both outcomes, environment receipt and closeout.

No effects, intervals, p-values or dataset decisions are printed or persisted
before the complete joint store is ready. A failure before atomic publication
leaves no partial outcome directory.

## Reconciliation

Verify every published byte and cross-artifact binding with:

```bash
python scripts/p2_confirmatory_closeout.py verify
```

The store contains:

- `registration.json` — immutable external registration evidence;
- `environment.json` — execution commit, interpreter, operating system and
  scientific package versions;
- `primary-outcome.json` — complete Telco split, controls and 180-replicate
  census;
- `replication-outcome.json` — complete Bank split, controls and 180-replicate
  census;
- `closeout.json` — frozen statistical decision and descriptive dose behavior;
- `store-manifest.json` — byte hashes and the store Merkle-style root.

Any changed, missing or independently substituted artifact fails verification.
An existing result directory cannot be overwritten or extended.

## Interpretation policy

The registered command does not optimize for a positive outcome.

- A technical or control failure invalidates the run; it is not scientific
  evidence for or against label noise.
- A primary failure preserves the uncovered mechanism and narrows the claim.
- A primary pass with replication failure permits only a Telco-bounded claim.
- A cross-dataset claim requires the same direction to pass the full rule in
  both datasets.
- Dose monotonicity and all secondary metrics are reported descriptively and
  cannot rescue the primary rule.
- No new rate, seed, model, endpoint, dataset or stopping decision may be added
  after outcomes.

The strongest allowed result remains bounded: the construct-aware gate may be
shown to detect the preregistered probabilistic degradation missed by the
accuracy-only legacy comparator in the studied dataset/model/noise setting. It
does not establish universal superiority or validate downstream AI diagnosis.
