# Registered v3.2 execution and atomic closeout

## Scope

This execution path implements the protocol registered by the immutable GitHub
release `p2-label-noise-shift-factorial-v3.2`. It does not alter the registered
datasets, partitions, preprocessing, models, intervention grid, seeds,
estimands, inference, thresholds or decision rules.

The runtime accepts exactly two protocol identities: the published v3.1
protocol and the published v3.2 recovery protocol. The v3.1 command remains
permanently disabled by its technical-failure receipt. Supporting its identity
inside deterministic primitives is required only to preserve existing evidence
verification and regression tests; it is not an execution route.

Every v3.2 model, prediction bundle, dataset attempt, inference result and
terminal store is bound directly to protocol SHA-256
`7cba25f08f4e27007bf17fc837b9f11137123f2f83452378c8ac3db5de3ffe27`.
No result is generated by relabeling a v3.1 artifact.

## Release-bound preflight

Preflight verifies all of the following before creating an idempotent local
registration receipt:

- the worktree is clean `main` and equals `origin/main`;
- the annotated v3.2 tag is an ancestor of the execution commit;
- the protocol stored at the tag has the registered canonical hash;
- the GitHub release is public, immutable, non-draft and non-prerelease;
- the two local archives reproduce the frozen dataset and split receipts;
- neither a sealed-open marker nor a terminal store exists; and
- the existing registration receipt, if any, contains identical evidence.

Preflight fits no model and opens no sealed test:

```bash
PYTHONPATH=src python scripts/p2_v3_2_confirmatory.py preflight
```

The returned protocol and registration hashes are the only confirmations
accepted by execution.

## Single sealed attempt

Execution creates an exclusive, fsynced sealed-open marker before loading the
registered dataset snapshots. The marker has no overwrite path. Its existence
blocks every later attempt regardless of whether the terminal disposition is a
scientific result, calibration abstention or technical failure.

Both datasets use the complete registered plan: 50 corruption seeds per cell,
50 environment seeds, all registered doses and directions, the full bootstrap,
sign-flip and MMD resampling counts, and the frozen primary and sensitivity
models. The primary and external-replication attempts remain in memory until a
single terminal store can publish them together.

Calibration non-convergence is the only defect converted to structured
`ABSTAIN`. The abstention contains its development-only numerical diagnostic,
contains no predictions or losses, exposes no reusable partial model and
blocks all dataset scoring. If either dataset abstains, the study closeout has
no dataset inference, no cross-dataset decision and no claim.

Any other exception is a technical failure. Its terminal receipt publishes the
exception class and a SHA-256 digest of the message, but no partial dataset
outcome. A failure still consumes the single v3.2 attempt and requires another
disclosed protocol for any recovery.

After preflight, the operator supplies both exact hashes:

```bash
caffeinate -dimsu env PYTHONPATH=src \
  python scripts/p2_v3_2_confirmatory.py execute \
  --confirm-protocol-sha256 <PROTOCOL_SHA256> \
  --confirm-registration-sha256 <REGISTRATION_SHA256>
```

This command must not be run from the feature branch. It is permitted only
after the execution implementation is merged, synchronized and has passed
preflight on clean `main`.

## Atomic terminal evidence

Scientific completion and calibration abstention atomically publish:

- `registration.json`;
- `environment.json`;
- `primary-attempt.json`;
- `replication-attempt.json`;
- `closeout.json`; and
- `store-manifest.json`.

A hard technical failure atomically publishes only registration, environment,
failure receipt and store manifest. Temporary directories are deleted on a
failed write, destination replacement is atomic, overwriting is forbidden and
the manifest content-addresses every byte plus the terminal artifact.

Verify the complete store independently:

```bash
PYTHONPATH=src python scripts/p2_v3_2_confirmatory.py verify
```

The terminal report is valid even when the scientific disposition is negative
or abstains. A passing software gate is not evidence that the scientific claim
passed; only the immutable closeout can establish that result.
