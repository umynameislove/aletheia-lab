# K07 synthetic consumer draft

Generated from current shared producer models by scripts/export_k07_contract.py. These examples are consumer drafts, not joint acceptance or deployment evidence.

preview-v1-draft preserves the original eight preview/mapping fixtures. uploads-v1-draft adds the current UploadManifest and UploadStatus schemas, a deterministic three-part synthetic ZIP manifest and new/partial/all-bytes-active/ready/cancelled/expired states. The ZIP bytes are generated in memory only and are not exported. Preview and upload examples are independent synthetic objects.

received_bytes counts verified bytes; active with all bytes is still awaiting complete/validation, and only ready has a source_id. Job progress remains null when unknown in the existing job contract.

problems-v1-draft uses the actual application._problem serializer. K07 codes are draft extensions; the generic shared Problem schema does not yet pin every K07 code/status pair. Consumers must check actual HTTP status, fail closed for unknown codes and coordinate the known-code registry through J01. No raw exception or private source path is included.

mapping-failure is a safe failed-job diagnostic envelope, not a standalone HTTP Problem or a successful result. Some illustrative mapping selections remain unresolved and are not a confirmable source fixture.

The exporter checks JSON Schema, model roundtrips, multipart hashes and progress semantics before writing. Identical files are retained; differing existing files stop the export before any write. manifest.json and SHA256SUMS.txt identify the exact generated bytes.
