4. ÁP DELTA TRÊN WINDOWS SAU KHI ĐÃ GIỮ LOG CŨ

Giải nén Cap-nhat-Kien-sau-chuyen-Windows-20261111.zip ra thư mục riêng.
Trong đó code/ có đúng 10 file: 8 file sửa và 2 file test mới. Danh sách cùng
SHA trước/sau ở changed-files.json. Đối chiếu SHA trước với source Windows;
nếu khác, giữ WIP và đọc diff trước khi ghép. Không ghi đè một bản đã sửa khác.

Sao lưu 8 file cũ, rồi chép nội dung code/ vào đúng source của gói Windows
(ví dụ C:\work\Aletheia-Windows-Docker\source), giữ cấu trúc thư mục. Không
chép vào .venv; không có dashboard file nên frontend Quân không bị thay đổi.
Không đổi dependency hay cần migration DB mới.

Nếu môi trường test đang dùng pip install -e thì source mới có hiệu lực ở
process kế tiếp; dùng chính Python của .venv đã tạo. Wheel đi kèm dành cho
nơi triển khai/cài package riêng; không cần cài wheel đè môi trường editable
để chạy bộ test source.

Từ source trong PowerShell, chạy focused trước:
  $aletheiaPython = (Resolve-Path .\.venv\Scripts\python.exe).Path
  $env:PYTHONUTF8 = '1'
  $env:PYTHONDONTWRITEBYTECODE = '1'
  & $aletheiaPython -B -m pytest -o addopts= -q -ra -p no:cacheprovider tests/unit/test_k03_renewal_creation_hint.py tests/unit/test_k06_api_shutdown_cleanup.py tests/unit/test_security_ci_contract.py

Sau đó chạy lại bộ Windows/PostgreSQL đã hướng dẫn, ghi log mới riêng. Giữ
K02–K07_TEST_DATABASE_URL trỏ đúng DB thử riêng và K02_TEST_HTTPS=1. POSIX
SIGTERM skip trên Windows native là ranh giới nền tảng, không sửa test cho qua.
Không bật Docker crash/IdP opt-in chỉ vì đã có container PostgreSQL smoke.
