10. HAI BÀI DOCKER RESTART/KILL — CONTAINER THỨ HAI RIÊNG

Chạy sau khi các bước4–9 đã xong, không cùng một lượt test khác. Đây là phần
có chủ đích restart và KILL DB; dùng container riêng cổng55434, anonymous
volume và guard. Không dùng container ở bước3 hoặc container của lượt cũ.

  $aletheiaRecoveryRun = [guid]::NewGuid().ToString('N')
  $aletheiaRecoveryName = "k06_recovery_$aletheiaRecoveryRun"
  docker run -d --name $aletheiaRecoveryName --label aletheia.owner=k06 --label "aletheia.run_id=$aletheiaRecoveryRun" -p 127.0.0.1:55434:5432 --mount type=volume,target=/var/lib/postgresql/data -e POSTGRES_USER=k06 -e POSTGRES_PASSWORD=synthetic_recovery_only -e POSTGRES_DB=k06_recovery postgres:16
  if ($LASTEXITCODE -ne 0) { throw 'Chưa tạo được recovery container.' }

Chờ lệnh này báo accepting connections:
  docker exec $aletheiaRecoveryName pg_isready -U k06 -d k06_recovery

Sau đó:
  $env:K06_RECOVERY_CONTAINER_ID = (docker inspect --format '{{.Id}}' $aletheiaRecoveryName).Trim()
  $env:K06_RECOVERY_IMAGE_ID = (docker inspect --format '{{.Image}}' $aletheiaRecoveryName).Trim()
  $env:K06_RECOVERY_CONTAINER_NAME = $aletheiaRecoveryName
  $env:K06_RECOVERY_PORT = '55434'
  $env:K06_RECOVERY_DATABASE_URL = 'postgresql://k06:synthetic_recovery_only@127.0.0.1:55434/k06_recovery'
  $env:K06_RECOVERY_ALLOW = 'owned-container-only'
  & $aletheiaPython -B .\run_windows_tests.py recovery
  if ($LASTEXITCODE -ne 0) { throw 'Docker recovery chưa đạt; giữ container/volume và logs.' }

Dự kiến2passed: graceful restart và crash/KILL, cùng volume/WAL durability.
Đây là committed source/job/audit trên profile experimental cũ; suite K09
hiện hành ở bước7 kiểm managed execution riêng. Hai bài này không thay tất
cả K09, realIdP hay joint UI acceptance. Guard từ chối thì giữ nguyên, không
bỏ label/identity/volume checks để ép chạy.

Sau lượt recovery:
  Get-ChildItem Env:K06_RECOVERY_* | Remove-Item
  docker stop $aletheiaRecoveryName
